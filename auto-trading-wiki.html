CHAPTER 1

Codex Desktop을 설치하고 프로젝트 폴더 지정하기

자동매매 플랫폼을 만들기 전에 먼저 정해야 할 것은 전략이 아닙니다. 한국투자증권 API도 아닙니다. 가장 먼저 해야 할 일은 Codex Desktop을 설치하고, Codex가 작업할 프로젝트 폴더를 정확히 지정하는 것입니다.

Codex는 단순히 질문에 답하는 채팅 도구가 아닙니다. 내 컴퓨터의 로컬 폴더를 열고, 파일을 읽고, PowerShell 명령을 실행하고, 필요한 코드를 만들거나 수정할 수 있는 개발 작업 도구입니다. 그래서 처음부터 어디에서 작업할 것인지를 정하지 않으면 파일이 예상하지 못한 위치에 생기거나, 나중에 로그와 결과 파일을 찾기 어려워질 수 있습니다.

01Codex Desktop 설치자동매매 프로젝트는 로컬 파일, 터미널, 실행 로그를 함께 다뤄야 하므로 데스크톱 환경이 적합합니다.
02전용 폴더 생성Windows 사용자 폴더 아래에 프로젝트 전용 폴더를 직접 만듭니다.
03작업 폴더 확인Codex가 현재 어떤 폴더를 보고 있는지 먼저 확인하고, 파일 생성은 그 다음에 진행합니다.

권장 폴더 위치

Windows에서 일반 사용자 폴더는 보통 C:\Users\사용자명\ 아래에 있습니다. 예를 들어 Windows 계정 이름이 minjun이라면 프로젝트 폴더는 다음처럼 만들 수 있습니다.

C:\Users\minjun\kospi200_auto_trading

이 위치가 좋은 이유는 경로가 짧고, 권한 문제가 적으며, 프로젝트 폴더 하나만 백업하면 코드, 설정 예시, 로그, 결과 파일을 함께 보관할 수 있기 때문입니다.

Codex에게 처음 요청할 문장

현재 Codex가 보고 있는 작업 폴더 위치를 알려줘.
파일 생성이나 수정은 하지 말고, 현재 경로와 폴더 안의 파일 목록만 확인해줘.

이 장을 마친 뒤 확인할 것

  • Codex가 현재 작업 폴더를 정확히 표시합니다.
  • 작업 폴더가 사용자가 의도한 위치입니다.
  • 파일을 만들기 전에 경로와 폴더 상태를 먼저 확인했습니다.
  • 프로젝트 전용 폴더 외부에서 작업하지 않습니다.

CHAPTER 2

한국투자증권 Open API를 Codex로 다루기

예전에는 증권사 Open API를 활용하려면 개발 역량이 상당히 필요했습니다. 개발자센터 문서를 읽고, 인증 방식과 토큰 발급 구조를 이해하고, 요청 헤더와 응답 코드를 직접 맞춰야 했습니다. 자동매매를 처음 접하는 사람에게는 API 문서만으로도 진입 장벽이 높았습니다.

Codex를 사용하면 이 과정을 작은 작업으로 나눌 수 있습니다. API 키를 어디에 넣어야 하는가, 조회 API와 주문 API는 어떻게 구분하는가, 아직 실전 주문은 호출하지 않고 토큰과 조회만 확인하려면 어떻게 해야 하는가처럼 범위를 좁혀 요청할 수 있습니다.

API를 바로 주문에 연결하지 않는 이유

한국투자증권 Open API에는 시세 조회, 계좌 조회, 주문 같은 여러 기능이 있습니다. 자동매매 플랫폼을 만들 때 가장 위험한 접근은 API 연결에 성공하자마자 주문 기능까지 열어두는 것입니다. 이 책에서는 조회 API부터 확인하고, 실전 주문은 안전장치가 준비된 뒤에만 검토합니다.

01API 신청한국투자증권 Open API 개발자센터에서 사용 신청과 모의투자 준비 상태를 확인합니다.
02설정 항목 정리App Key, App Secret, 계좌번호, 실행 모드를 config/.env 기준으로 관리합니다.
03조회부터 검증토큰 발급과 시세 조회를 먼저 확인하고, 주문 API 호출은 제외합니다.

설정은 config/.env 하나로 고정

초보 독자에게 환경변수 또는 .env 중 선택처럼 설명하면 오히려 혼란이 커집니다. 이 위키에서는 설정 위치를 config/.env로 고정합니다. 실제 API 키와 계좌 정보는 공개 페이지나 예시 코드에 그대로 적지 않습니다.

KIS_APP_KEY=실제값은_공개하지_않음
KIS_APP_SECRET=실제값은_공개하지_않음
KIS_ACCOUNT_NO=실제값은_공개하지_않음
RUN_MODE=paper

Codex에게 다시 요청할 문장

한국투자증권 Open API 설정 항목을 정리해줘.
설정은 config/.env 파일에서만 읽는 구조로 설명해줘.
아직 파일을 만들지 말고, 필요한 설정 이름과 각 항목의 의미만 표로 정리해줘.

이 장을 마친 뒤 확인할 것

  • API 키와 계좌 정보가 어떤 용도로 쓰이는지 설명할 수 있습니다.
  • 실전 주문 API는 아직 호출하지 않습니다.
  • 조회 API부터 테스트해야 한다는 순서를 이해했습니다.
  • .env에 넣을 항목과 공개하면 안 되는 실제 값을 구분했습니다.

CHAPTER 3

코스피200과 CCI 전략 기준 정하기

자동매매를 시작할 때 거래 대상을 너무 넓게 잡으면 검증 범위가 커집니다. 주식은 위험 자산이고, 특히 변동성이 높은 코스닥이나 중소형주는 초보자가 자동매매의 기본 구조를 검증하기에 부담이 클 수 있습니다. 그래서 이 책에서는 거래 대상을 코스피200으로 제한합니다.

코스피200은 유가증권시장에 상장된 대표 종목군을 바탕으로 구성되는 지수입니다. 시장 전체를 완전히 대신한다고 볼 수는 없지만, 시가총액과 유동성 측면에서 비교적 대표성이 높은 종목들이 포함됩니다. 자동매매 초반에는 거래 대상을 넓히기보다 관리 가능한 범위로 줄이는 것이 중요합니다.

왜 코스피200인가

  • 거래 대상을 코스피 시가총액 상위권 중심으로 좁혀 리스크를 줄이고자 했습니다.
  • 중소형주나 테마주보다 데이터 확인과 대상 관리가 단순합니다.
  • 자동매매 플랫폼의 목적이 종목 발굴이 아니라 규칙 실행과 기록 검증이라는 점에 맞습니다.

왜 CCI인가

CCI는 가격이 최근 평균적인 움직임에서 얼마나 벗어나 있는지를 보는 기술적 지표입니다. 이 책에서는 평균에서 많이 벗어난 가격은 다시 평균적인 범위 안으로 돌아올 수 있다는 생각을 신호 발생 기준으로 삼았습니다. 다만 이것은 수익을 보장하는 원리가 아닙니다. 가격은 계속 한 방향으로 움직일 수도 있고, 지표가 예상과 다르게 작동할 수도 있습니다.

CCI를 선택한 또 다른 이유는 이동평균을 기반으로 한 널리 알려진 지표라서 초보자가 개념을 따라가기 쉽기 때문입니다. 복잡한 모델을 처음부터 쓰기보다, 가격 데이터와 계산 결과를 직접 확인할 수 있는 기초 지표로 시작합니다.

01대상 고정거래 대상을 코스피200으로 제한합니다.
02지표 고정신호 기준은 CCI로 시작합니다.
03기록 우선신호가 맞았는지 틀렸는지보다, 어떤 데이터로 어떤 신호가 나왔는지를 먼저 기록합니다.

Codex에게 다시 요청할 문장

코스피200을 거래 대상으로 고정하고, CCI를 신호 기준으로 사용하는 이유를 초보 독자가 이해할 수 있게 정리해줘.
수익 보장이나 매매 권유처럼 보이는 표현은 제외해줘.

이 장을 마친 뒤 확인할 것

  • 거래 대상이 코스닥, 중소형주, 전체 종목으로 확장되지 않습니다.
  • 코스피200과 CCI 기준이 명확히 고정되어 있습니다.
  • CCI 신호가 매수, 매도, 대기 중 하나로 구분된다는 흐름을 이해했습니다.
  • 지표 설명이 투자 추천처럼 보이지 않습니다.
